All new game reads use the existing `ns.Call` (nil/function check plus pcall), `AsNumber`/`SafeString`, and `Snapshot.Clean` secret-value filters. The scheduler refuses reads in combat and with sharing off. Trainer and vendor reads scan at most 1,000 API entries per settled event; latest 200 unique NPC/recipe or NPC/item pairs survive per Character Section. There is no new ticker or per-frame scan. No purchase, training, filter mutation or secure-frame call is made.

Forever UiMap enUS was fetched from [wago.tools, build 1.60.1.70888](https://wago.tools/db2/UiMap/csv?build=1.60.1.70888&locale=enUS). The small fixture preserves `1429 = Elwynn Forest` and `1453 = Stormwind City`; Retail's superficially similar zone ids are not reused. The full table has 60 rows. Synthetic NPC ids in tests are not place evidence.

## Resolution and remaining evidence

Spell ids must occur in the current game's profession catalog. Vendor items resolve through all matching `teachingItems`. Names resolve by exact, unique English name within a skill line only with `locale=enUS`; non-enUS, ambiguous or unknown names stay unresolved. Reads resolve again against the current catalog, so a later import can resolve an older sighting without another visit. The stored nullable `recipe_spell_id` records the resolution at ingest; it is not authoritative after a catalog change.

There are **no real player sightings in this change**. The shared synthetic fixture has five observations: four resolve and one non-enUS name remains unresolved. The live count is unknown until Nick visits trainers/vendors. An owner can inspect unresolved rows with `SELECT game, kind, count(*) FROM recipe_sightings WHERE recipe_spell_id IS NULL GROUP BY game, kind`; ids and per-Account counts never leave through source reads or the website.

The teaching map omits an item with conflicting spell/profession/minimum-skill tuples. Advice requires observed profession data and an explicit `GetRecipeInfo.learned=false` observation; absence from a filtered learned list never proves a recipe is new. While the own profession window is open, the existing staged collector also probes delivered teaching-map spell ids directly and stores the optional Packed `unlearned` set; unavailable/secret results stay silent. It checks the current Character first, then an eligible same-game Alt observed in this Account's SavedVariables. Alt Advice requires enough skill and is suppressed for a soulbound item. Missing recipes appear in the first applicable source group, but every observed source remains visible under the recipe. Limited supply is past stock evidence, not live availability.

A future vetted Catalog drop/quest source can extend the shared `RecipeSource` union and grouping once it has a primary source URL. T4 supplies no drop/quest links, inferred NPCs, third-party database rows or images. Skill-up routes, history and release claims remain T5–T7.
