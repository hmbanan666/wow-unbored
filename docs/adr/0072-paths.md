# 0072. Paths

Status: accepted

A **Path** is a curated set of goals for one piece of content ("Midnight: Basic"). It has a tier (Basic, Deeper, Complete; a deeper tier lists the previous one as prerequisite) and optional **Topics** (mounts, achievements, PvP) that group its goals. Each **Path goal** is one Plan outcome kind (rep, renown, level, achievement, currency, mount, pet, toy, item) or `quest` / `questLine`, referencing ids verified in the Game DB, with an optional required flag (required goals define completion). Paths are versioned rows in Postgres (schema `content`, with draft and published states), drafted with sources through owner tools that check every id against the Game DB on save and publish; players do not author them. Progress is computed by the Server per Character from the Game data snapshot (account-wide goals from Account Sections), as done of total required goals. A Character has at most one active Path, set from the website or an in-game Idea; Ideas offer "Continue your Path" and Plans for it take their outcome from the next unfinished goals. Reaching all required goals records a **Path completion** in Player history (once per Character and Path version), like a Win.

**Kinds.** A Path has a kind: `path` (tiered goals for one piece of content, as above) or `collection`, an authored top list such as "Top 50 mounts to get first" or "Top 50 pets to farm first". A collection has no tier or prerequisite; its goals are ordered items, each a verified Game DB target (mount, pet, toy, achievement, item) with its source and a short how-to note. Progress (X / Y), the active Path, Plans from it and Path completion work the same for both kinds, and both get a public page (0074). Collections are entry points, not a knowledge base: no page per game object.

**Item fields.** A Path goal (and so a Collection item) stores, besides its kind and verified id: its position, the game name of that build, a source (type: vendor, drop, quest, achievement, reputation, renown, profession, PvP, event, treasure, other; the client's source text; the zone as a UiMap id when known; the cost when known), whether the source is a chance drop, a short original how-to note, and a source URL for anything the Game DB does not hold. A chance-only item can be listed and counted, but is never a Plan outcome (0071); its Plans treat it as a bonus.
