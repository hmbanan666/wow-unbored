# 0022. Releases and docs for players

Status: accepted

A release body says only what changed in that release, grouped as Features, Fixes, Performance and Other with one short line and a commit link each, generated by git-cliff from Conventional Commits (feat, fix, perf, refactor, docs, chore, plus test and ci, with a scope); PR titles follow the same form and CI checks them, and `CHANGELOG.md` stays as history but is never pasted into a release. Every release body starts with a short Install / Download section for a first-time, non-technical player that names the one file to download, gives two or three steps, links the README, and marks technical files (`latest.json`, `.sig`, `release.json`) as for auto-update only. The README is written for players first (what Wisp is, a picture, Install in three steps, what Wisp can do, FAQ, in English with a Russian section), and technical content lives in `docs/DEVELOPMENT.md` (D44-D46).
