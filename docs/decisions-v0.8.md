## A. Companion: Wisp picture is gone after 0.7.0 (bug)

Root cause (read from code): PR #16 (`efb648e`, first shipped in v0.7.0) moved the Companion UI under Vite (`apps/companion/vite.config.ts`, `root: "ui"`, `outDir: "../dist"`, `tauri.conf.json` `frontendDist: "../dist"`; v0.6.0 served `companion/ui` as is). `index.html` has a static `img/wisp-idle.png` that Vite rewrites to a hashed asset, but `ui/app.ts:42` sets `mascot.src = \`img/wisp-${...}.png\`` at runtime. Vite never copies `ui/img/` into `dist/` (it is not `publicDir` and not imported), so the first `paint()` points the `<img>` at a missing file and the picture disappears.

- D83 Q: Fix? A: import the three pictures in `app.ts` (`import idle from "./img/wisp-idle.png"` etc.) and map phase -> imported URL; keep the static `src` in `index.html` as the first frame. Reason: Vite then fingerprints and ships them; no reliance on a `public/` convention a later refactor can break again.
- D84 Q: Guard against a repeat? A: a check after `vp build` in `companion.yml` (and the release dry run, D117) that `dist/` contains a `wisp-idle`, `wisp-happy`, `wisp-thinking` asset and that `dist/index.html` references no path missing from `dist/`. Reason: the regression was silent; a 5-line script makes it loud.

## C. Waiting animation (avatar jumps at the end / top)

Root cause (code): `bob()` and `pulse()` in `UI/Mascot.lua:210-246` loop with `SetLooping("BOUNCE")`, and `SetMood` calls `group:Stop()` when thinking ends. `Stop()` snaps the Translation back to 0 from wherever it is (up to +4 px at the top) and resets alpha in the same frame, and the texture swap to happy/idle happens in the same call: that is the visible jump. BOUNCE also reverses abruptly at the apex.

- D88 Q: New animation? A: one AnimationGroup per effect, created once:
  - float: `REPEAT` loop of two Translation anims (order 1: +3 px in 1.2 s, order 2: -3 px in 1.2 s), smoothing `IN_OUT` each, so every loop starts and ends at offset 0;
  - glow: `REPEAT` loop of Alpha 1 -> 0.85 (1.2 s) and 0.85 -> 1 (1.2 s), same timing as the float;
  - to stop, call `group:Finish()` (runs to the end of the current loop, then stops at 0), never `Stop()`; the texture swap waits for `OnFinished` of the float (cap 2.4 s), and a mood change during finish just updates the pending texture;
  - `Refresh()` never touches the groups; only `SetMood` does, and only on change.
  Reason: symmetric loops plus Finish remove the snap; this is the standard pattern used by Blizzard's own UI pulses. **verify in game**: `Finish()` on a REPEAT group in 12.x.
- D89 Q: Also lock text while waiting? A: unchanged from D67, but the waiting Bubble gets a quiet three-dot "thinking" text animation in the header (alpha cycle on three font strings, same group rules), not a spinner. Reason: one gentle sign of life without moving the avatar more.

- D91 Q: Card layout (top to bottom), quest log style? A:
  1. **Title row**: plan title in quest-title gold (`GameFontNormal` colour, `QuestTitleFont` if it fits the width), menu and collapse icons on the right. No numbers in this row.
  2. **Progress pips**: one thin row of small pips (filled = done, ring = current, dim = ahead, max 12 shown then "+N"), hover tooltip "Step 2 of 5". Replaces "2/5".
  3. **Goal line** (only while the card is expanded or on the first step): `plan.goal`, one sentence, white-ish, may carry links.
  4. **Current step**: step title as "what to do" (`GameFontHighlight`, white), then `why` in muted text if present.
  5. **Details** toggle (text button "Details" / "Подробнее" with chevron, collapsed by default, remembered per plan): step `note`, plan `details` (facts like "you have 3,200 Timewarped Badges"), condition progress (D95).
  6. **Next** (collapsed preview by default): up to 3 upcoming step titles, muted, one line each with links as plain coloured text; a "All 5 steps" toggle expands the full list inline (scroll frame inside the Bubble, max height ~ 260 px), clicking a row shows that step's details; finished steps struck/dimmed. This is everything the Tracker window offered.
  7. **Rewards** (quest style "You will get:" / "Награда:" header): icons + native links from `plan.rewards` (and the current step's `rewards`), up to 6, icon 16 px with the link text; tooltip on hover via the link.
  8. **Footer**: one muted small line, right aligned: distance and time, formatted "about 25 min" / "about 1 h 40 min" ("около 25 мин", "около 1 ч 40 мин"), no `~`. Time shows only when `estMinutes` exists; plan-level time left is not shown on the card (it stays in the step-pips tooltip as "about N h left").
  9. **Buttons**: [Done] [Skip] only. Everything else in the right-click / `...` menu.
  Reason: mirrors the quest log the player already reads (title, objective, description, rewards) and keeps one window.
- D92 Q: Bubble width? A: 260 -> **300** px for the step card only (other views stay 260); bubble scale setting still applies. Reason: a reward row and two-line titles need room; quest log text width is similar.
- D93 Q: Plan-level schema? A: additive fields on Plan v1 (no version bump; all optional, old plans keep working):
  - `title` string, 3-40 characters, human and catchy like a quest title, no ids, no numbers unless part of a name, no "you have", no link tokens;
  - `goal` string, at most 160 bytes, one sentence: what you do and why it is worth it; may carry link tokens;
  - `details` string, at most 600 bytes: facts and state (currency counts, what alts already did), may carry tokens;
  - `rewards` array of up to 6 link tokens as strings (`"{mount:1234}"`, `"{ach:291}"`, `"{item:..}"`, `"{toy:..}"`, `"{currency:..}"`, `"{pet:..}"`, `"{title:..}"` is not added, see D99).
  Per task, optional: `why` (at most 120 bytes, tokens allowed), `rewards` (up to 3 tokens), `condition` (D95).
  `note` stays for the step's long text. Reason: maps 1:1 to quest title / objective / description / rewards.
- D94 Q: Server enforcement of a human title? A: `put_plan` (and `answer_request` with a plan) checks `title`: length 3-40 chars; no `{` tokens; no more than one digit group; not starting with a mode/preset key; not equal to the request wish. Violations are **warnings** in the reply and the server falls back: over 40 chars -> cut at the last word boundary before 40 with no ellipsis; missing title -> warning "add a short human title" and the addon falls back to the preset label. The `put_plan` description gets a TITLE rule with good/bad examples (good: "Badges for a Timereaver", "Hallow's End in one evening"; bad: "Warlords Timewalking: you have 3200 currency", "Plan for request mode surprise"), plus "state facts go in details". Reason: the LLM follows examples best; warnings keep the plan usable.
- D95 Q: Conditional steps ("if you have 5,000 badges, buy the mount")? A: task `condition = { text = "If you have 5,000 {currency:1166}", check = { kind = "currency"|"item"|"level"|"quest"|"ach", id = <int>, atLeast = <int>? } }`. `text` is shown before the step title as a muted "If ..." line; `check` is evaluated live in the addon (`C_CurrencyInfo.GetCurrencyInfo(id).quantity`, `C_Item.GetItemCount(id, true)`, `UnitLevel`, `C_QuestLog.IsQuestFlaggedCompleted`, `select(4, GetAchievementInfo(id))`); met -> green "Ready" tag; unmet -> "3,200 / 5,000" progress in Details and the step is shown but marked "not yet", and Skip on it moves past without counting as skipped. No check -> text only. Reason: the game already knows the numbers; the plan should not guess them.
- D96 Q: Old plans (0.7) on the new card? A: no `title` -> preset label (`PRESET_*`) or `PLAN_NAME_DEFAULT` ("Your plan"); `PlanName()` **stops using `note` as a title** (the source of the ugly title); `note` shows in Details. No `rewards` -> no reward row. Reason: backward compatible and never shows a technical string as a title.
- D97 Q: Quick plans (local providers)? A: the addon builds `title`/`goal`/`rewards` for its own Quick plans from the provider data it already has (holiday name, achievement link, mount from `Data/Holidays.lua`), so local plans get the same card. Reason: one look for every plan.

## F. Suggestions from the player's data instead of typing (item 7)

- D103 Q: Who computes Suggestions? A: **the Server, deterministically, with no LLM call**, on every `/v1/snapshot` upload (debounced 30 s per Account), cached per Character in `suggestions(owner_id, character_id, computed_at, body_json)`. Reason: arrives offline with the data, costs nothing per session, and never invents an id because it only combines the player's data with a catalog of known ids.
- D104 Q: Source of known ids (catalog)? A: the addon's curated data is the single source: `addon/Data/Holidays.lua`, `FunAchievements.lua`, `Exploration.lua`, `Rares.lua`, `Farm.lua`. A script (`scripts/export-catalog.lua`, run with the existing Lua test runner) exports them to `packages/contracts/catalog/catalog.json`; a test fails when the JSON is out of date. The server reads that JSON. New catalog rows (for example Timewalking events and their rewards) are added only with a primary source URL in a comment (warcraft.wiki.gg / wowhead) exactly like the existing header rules; if unsure, leave the row out. Reason: ids are already vetted there; one source for Lua and server.
- D105 Q: Rules (v1, ranked by score)? A:
  1. **Event**: a holiday or Timewalking in the `calendar` section active now or starting within 3 days -> its catalog tasks whose achievement/mount is not done or owned by anyone on the Account (`achievements`, `mounts` sets) -> one suggestion per event (title = event name, rewards = the missing mount/achievement tokens, expires = event end). Score 100, +20 if it ends within 3 days.
  2. **Nearby achievement**: catalog achievements with a `mapID` equal to the current or most-played zones of the last 3 sessions (`sessions`), not completed on the Account. Score 60.
  3. **Rare / treasure**: `Rares.lua` rows with `questID` not in this Character's `questsDone`, in the current zone or a recent one. Score 50.
  4. **Collection**: catalog mounts/toys/pets with a known source not owned on the Account (`mounts`/`toys`/`pets`), preferring ones tied to rules 1-3 zones. Score 40.
  5. **Alt-aware bonus**: +10 when the suggestion fits this Character but not the others (for example quest not done here). Shown as `why` ("None of your 7 characters has it yet").
  Top 6 per Character, at most 2 per rule, deduped by reward id. Reason: these are the four kinds the owner named (nearby achievements, rares/mounts, current events) plus the Account angle that is our moat.
- D106 Q: Suggestion contract? A: `packages/contracts/schema/suggestions.schema.json`: `{ v = 1, computedAt, characters = { ["Realm-Name"] = { { id, kind = "event"|"achievement"|"rare"|"collection", title (<= 40, human), goal (<= 140 bytes, tokens ok), why (<= 100 bytes, optional), rewards = { tokens, <= 3 }, mapID?, expiresAt?, request = { topic = "suggestion", suggestionId, wish = <goal plain text> } } } } }`, fixtures in Lua and JSON read by Lua, Rust, TS tests. Reason: same contract discipline as plans and markup.
- D107 Q: How do Suggestions reach the game? A: like Personal advice: Companion fetches `GET /v1/suggestions` (device auth, the Account's characters on this install) on each sync and writes `Interface/AddOns/Unbored_Plan/Suggestions.lua` (`UnboredSuggestions = {...}`), added to the helper TOC, inside the D76 Prefetch budget (suggestions <= 20 KB, <= 2k literals); unchanged content -> file not rewritten. The addon reads it at login/reload. Reason: proven path, no new mechanism, works offline.
- D108 Q: How does the choice Bubble look? A: "What shall we do?" then **up to 4 Suggestion chips** (title in white, one reward icon on the right, a muted `why` or "ends in 2 days" under the title; hover tooltip shows goal + rewards), then a single row of two small chips **[Surprise me] [Something else]**, and a "More ideas" text toggle that reveals the six old presets (nearby, mount, collect, grind, gold) inline. With no Suggestions (no Companion, no data, or all expired) the six presets show as today. Reason: owner: players do not know what they want; show ideas first, keep the old paths one click away, fewer buttons.
- D109 Q: Picking a Suggestion? A: chip -> Confirm (title + goal + rewards, [Send now]) -> Request `plan` with `topic = "suggestion"`, `suggestionId`, the suggestion body copied into the Request (so the Planner gets ids from it), **no time field**. If the suggestion has a local Quick plan form (event/rare with known coords) the Quick plan starts at once as today and [Want a proper plan?] offers the Request. Reason: same D65 flow; the Planner gets grounded ids.
- D110 Q: Time budget anywhere? A: only the optional minutes field in Something else (ADR 0037 unchanged). Presets and Suggestions never ask for time. Reason: owner rule.
- D111 Q: Local live fallback without the Server? A: the addon also builds up to 2 live Suggestions itself from what it already detects (active holiday via its calendar read + `Data/Holidays.lua`, current-zone vignettes/rares) and merges them, server ones first, deduped by reward/achievement id. Reason: the addon-only player still gets ideas; no new data paths.
- D112 Q: MCP? A: `get_suggestions(account?, character?)` (read, for the Planner and the owner) and the `list_requests` description explains `topic = "suggestion"` and that `suggestion` in the request is ground truth for ids. No `put_suggestions` for the Planner in 0.8 (a later idea: the Planner adds "next ideas" when it already runs). Reason: start deterministic, measure, then add LLM ideas.
