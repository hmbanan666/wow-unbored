# Проверка перед клиентом (0.12)

Короткий чек-лист для живого клиента WoW (Retail, Windows). Галочка — работает как написано. Если нет — `/unbored errors` и скрин; бот смотрит то же через MCP `list_errors`.

Главное: за всю проверку UI перезагружается только когда ты сам нажал «Отправить», «Обновить» или «Загрузить» после обновления аддона. Ни одна идея, пресет или предмет сами не перезагружают. Нигде нет поля для текста и нигде не спрашивают про время. Окна вставки (`/unbored import`, `/unbored export`) больше нет.

## Карточка плана (0.12)

- [ ] Получить новый план: карточка свёрнута, видны название с иконкой награды, живая полоска сразу под ним и действие; «Шаг N из M» (только для двух и более шагов) и время стоят в той же строке. Поля для ввода нет. Раскрыть старый план, затем принять новый: новый снова свёрнут, даже со старым сохранённым раскрытием из 0.11. Внутри одного плана раскрытие сохраняется при смене шага и после входа.
- [ ] Один переключатель «Подробнее / Свернуть» (EN: More / Less) открывает цель, детали, примечание, список шагов, отличающиеся награды, бонус и подсказку пути. Второго переключателя нет; длинное примечание прокручивается. Следующий шаг сохраняет раскрытие.
- [ ] Репутация: на примере Спореггара до уважения видны название фракции, нужный и текущий ранги и живая полоска `5 885 / 6 000` (разделитель зависит от клиента). Получить репутацию — полоска меняется без перезагрузки. Достичь цели — «Готово». Проверить также дружбу, максимальную репутацию и идеальную репутацию: нет деления на ноль и бесконечной полоски.
- [ ] Известность: текущий уровень и прогресс до следующего; уровень персонажа: текущий уровень и опыт. Получить известность/опыт — обновление без кликов. Выполнить критерий достижения — меняется число выполненных критериев; получить достижение — «Готово». Один критерий «победить 50» показывает `17 / 50`, а не `0 / 1`.
- [ ] Фракция с идеальной репутацией: при дружелюбии цель «Почтение» ещё не готова; при превознесении — «Готово».
- [ ] Предмет для результата лежит только в банке реагентов или только в банке отряда: «Готово». Переместить последний экземпляр в банк и обратно, затем убрать из владения: открытая карточка обновляется без перезагрузки.
- [ ] Валюта: сколько есть / сколько нужно. Получить предмет, выучить маунта, питомца или игрушку — результат становится «Готово». Без данных игры остаётся подпись без выдуманного прогресса и без ошибки Lua. В раскрытой карточке возможный бонус — отдельная мелкая строка, явно не обещанная награда. Старый план без результата показывает прежнюю награду.
- [ ] Начать бой во время изменения прогресса, затем выйти из боя: чтения и обновление откладываются до конца боя, без ошибок и защищённых действий.
- [ ] Находясь в Калимдоре, открыть шаг с точкой в Зангартопи: есть строка про Запределье, нет стрелки в никуда (проверить также с дополнительной стрелкой). Перейти в Запределье — точка и стрелка появляются сами, строка исчезает. В пределах одного континента всё работает как раньше; чужая метка на карте не удаляется.
- [ ] На плане «Void Bane: Zul'Aman» с прогрессом 32/50 название не повторяется в результате, цели и наградах; при сворачивании старое «19 осталось» из цели не видно. Иконка у названия показывает игровую подсказку; кнопки подписаны, наведение даёт «Готово / Пропустить» (EN: Done / Skip). Раскрыть и свернуть три раза: полоска остаётся под названием без рамки, детали скрываются; ничего не висит отдельно. Проверить русский и английский, масштабы 80, 100, 125 и 150 %, длинные названия.
- [ ] «Настройки» → «Самопроверка» (EN: Self-check): результат появляется без команд и перезагрузки; в бою предлагается повторить позже. Подробные проверки — ниже.
- [ ] После «Забыть мои данные» нажать «Подключить снова» (EN: Connect again), закрыть Companion во время подключения и открыть: повторное подключение заканчивается без потери данных и без повторного ввода. Подробные проверки восстановления — ниже.
- [ ] С повреждённым `settings.json` Companion открывается с понятным сообщением, сохраняет повреждённую копию и даёт настроить подключение заново; проверить также запуск с `--hidden`. Подробные проверки настроек — ниже.
- [ ] Когда этот ПК одобрен, кнопка «Моя страница» (EN: My page) открывает браузер без ввода. На странице свои персонажи, уровень и история планов; чужих имён нет. Та же ссылка второй раз не открывает страницу. «Забыть мои данные» закрывает её: снова нужна кнопка в Companion.

## Планы от сервера (0.12)

- [ ] «Удиви меня» и идея на репутацию: оба полных плана называют конкретную цель в названии и показывают её в значке результата.
- [ ] Последний шаг завершает обещанную цель; возможная случайная награда отмечена только как бонус.
- [ ] В шагах только действия и короткие пояснения, без рассуждений о выборе плана или проверке данных.
- [ ] Шаттрат и похожие зоны на другом континенте указаны с континентом в скобках.
- [ ] Во время запроса плана сервер отвечает без задержек, проверка здоровья остаётся `ok`.
- [ ] Развернуть новую версию сервера во время запроса плана: Plan runner не получает `502`, план сохраняется один раз ([завершение работы сервера](docs/DEVELOPMENT.md#server-deploys), PR #79).
- [ ] Выгрузить данные Account с одного персонажа, затем более позднее сохранение другого персонажа со старым чтением той же Section: остаётся Section с более новым `at`, о старой — одна строка в логе, результат выгрузки содержит `sections` со статусом `stale` ([ADR 0063](docs/adr/0063-section-freshness.md)).

## Самопроверка игровых API

- [ ] Правый клик по Бори → «Настройки» → «Самопроверка» (EN: Settings → Self-check). Без команд и перезагрузки появляется «Самопроверка готова: успешно — N, с ошибкой — M»; окна игры, фильтры и чат не меняются.
- [ ] Если бой начался при открытом меню, кнопка просит повторить проверку после боя и ничего не читает. После боя её можно нажать снова.
- [ ] После обычного выхода или смены персонажа Companion отправляет одну строку `where=selfcheck` в `list_errors`: сборка игры и счётчики в `text`, все API и статусы `ok` / `error` / `manual` в `stack`. Для `ok` видны типы, ограниченные счётчики и известные ключи, без имён, значений, текста исключений и содержимого стека. Последняя строка — `C_Calendar.GetDayEvent`.
- [ ] При выключенной передаче данных результат остаётся на ПК. Повторная проверка с теми же счётчиками обновляет подробности; обычные ошибки продолжают приходить как раньше.
- [ ] `ok` означает только успешный вызов: отдельно проверить пункты `manual` и примечания — восстановление фильтров и заголовков, доставку событий календаря и рейтинга, соответствие цепочек главам кампании, порядок заданий, длительность прохода достижений, чат без taint, ссылки на питомца/подземелье и анимации Бори. Самопроверка не открывает эти окна и не запускает такие действия.

## Короткие планы и точки назначения

- [ ] Полный план на русском и английском: заголовок шага — одно короткое действие с целью и завершением; подробности — не больше двух коротких предложений. Нет объяснений «по вашим данным», отвергнутых вариантов и больше одной шутки на план.
- [ ] Поездка на другой континент: у города и зоны указан континент или дополнение в скобках, портал назван как в клиенте. Первая стрелка ведёт к месту назначения; если точка неизвестна, стрелки нет. Она не указывает на место, где персонаж стоял при отправке запроса.

## Повреждённые настройки Companion

- [ ] Закрыть Companion, сохранить свою копию `settings.json` и записать в него незавершённый JSON. После запуска рядом появился `settings.json.bad-<UTC timestamp>` с исходным содержимым, Companion начал с настроек по умолчанию, а над обычными действиями видно сообщение с именем копии.
- [ ] Проверить сообщение на английской и русской Windows. «Dismiss» / «Понятно» скрывает его; проверка в фоне и повторное открытие из трея его не возвращают. После перезапуска с исправными настройками сообщения нет; новое повреждение создаёт новую копию и новое сообщение.
- [ ] Запуск с `--hidden` и повреждёнными настройками всё равно открывает окно с сообщением. Старые `.bad` файлы сохраняются без изменений.
- [ ] Отсутствующий `settings.json` (первый запуск) не вызывает сообщение. Запрет чтения существующего файла вызывает сохранение и сообщение, если права позволяют переименование; если сохранить копию невозможно, сообщение честно сообщает об этом, а исходный файл не заменяется.
