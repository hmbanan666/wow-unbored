# Проверка перед клиентом (0.7.0)

Короткий чек-лист для живого клиента WoW (Retail, Windows). Галочка — работает как написано. Если нет — `/unbored errors` и скрин.

Главное: за всю проверку UI перезагружается только когда ты сам нажал «Отправить», «Обновить» или «Загрузить» после обновления аддона. Ни одна кнопка пресета, вопрос или предмет сами не перезагружают.

## Релиз

С 0.7 один тег `vX.Y.Z` содержит установщик, zip аддона и `latest.json`. Уже установленные Companion 0.5 и 0.6 по-прежнему читают `latest.json` с релиза `companion-updater`. Пункты ниже проверяют уже вышедший 0.6.0.

- [ ] В релизе `companion-v0.6.0` текст начинается с «Install / Download»: какой файл скачать (`..._x64-setup.exe`), 2–3 шага, ссылка на README. `latest.json` и `.sig` подписаны как «для автообновления, не трогай».
- [ ] Ниже — только изменения 0.6.0 (Features / Fixes / Performance / Other), а не весь CHANGELOG.
- [ ] То же в релизе аддона `v0.6.0`: «Install / Download» про zip для ручной установки и совет брать Companion.
- [ ] README открывается по-человечески: что такое Wisp, картинка, установка в 3 шага, FAQ, раздел «По-русски».

## Установка

- [ ] Скачать `Unbored.Companion_0.6.0_x64-setup.exe` из релиза `companion-v0.6.0`. SmartScreen: «Подробнее» → «Выполнить в любом случае».
- [ ] Окно Companion: «Connecting...», потом «Waiting for a one-time OK» с именем ПК.
- [ ] В списке шагов: папка WoW найдена, Wisp установлен (0.6.0) — ещё до одобрения.
- [ ] Одобрить ПК (MCP `list_devices` → `approve_device`).
- [ ] Не позже чем через 30 с: тост «You're connected!» и «Connected! You're all set».
- [ ] В `Interface/AddOns/Unbored_Plan/` есть `Plan.lua` и `Advice.lua`.

## Первый вход

- [ ] Запустить WoW, войти персонажем. Без `/reload` и команд.
- [ ] Wisp здоровается «Привет! Чем займёмся?» и показывает пресеты.
- [ ] Кнопка у миникарты сидит на ободке, её можно тащить по кругу. ЛКМ — показать/спрятать Wisp, ПКМ — меню.
- [ ] Нет красных ошибок Lua, нет «интерфейс заблокирован» (taint).

## Облачко и меню

- [ ] Длинный текст: облачко растёт, ничего не обрезано и не вылезает за край.
- [ ] ПКМ по Wisp → «Настройки»: «Размер Wisp» и «Размер облачка» меняются отдельно, «Закрепить на месте», «Спрятать», «Клавиши», «Ещё».
- [ ] Клик по Wisp сворачивает облачко в маленькую плашку; клик по плашке — обратно.

## План без перезагрузки

- [ ] Под пресетами нет выбора времени (раньше 30м / 1ч / 2ч), и после пресета Wisp не спрашивает, сколько у тебя времени.
- [ ] «Что-то другое...»: под полем желания пустое поле «Минуты, только если есть лимит». Оставить пустым → в MCP `list_requests` у запроса `budget: null`. Ввести 45 → `budget: 45`. Ввести 300 → «Минуты: целое число от 5 до 240, или оставь пустым.», запрос не ушёл.
- [ ] Свой план на большую ачивку (например, с 18 критериями): у планировщика (`put_plan`) в плане все критерии по порядку, план не урезан до 7 шагов и не подогнан под время. Минуты у шагов — только справка.
- [ ] Нажать пресет (например «Добыть маунта»). UI **не** перезагружается. Сразу виден быстрый шаг и кнопка «Хочешь настоящий план?».
- [ ] Если быстро ничего нет: «Быстро тут ничего нет. Подумать как следует?» и сразу поле «Что-то добавить? Можно пропустить.».
- [ ] «Хочешь настоящий план?» → «Что-то добавить? Можно пропустить.» → «Дальше» (можно пустым) → «Отправить это планировщику?» с кратким пересказом выбора и кнопками «Отправить», «или при выходе», «Назад».
- [ ] «Назад» на каждом шаге возвращает на шаг раньше, ничего не отправив.
- [ ] «Отправить» → один `/reload` от клика → «Я этим занят. Обычно пара минут. Играй, я дам знать.», Wisp мягко пульсирует и покачивается. Быстрый шаг (если был) остаётся выполнимым.
- [ ] Пока запрос в работе, пресеты, «Спросить» и предметы отвечают «По одному делу за раз, я ещё думаю.». В меню есть «Отменить мой запрос»; после него Wisp снова свободен.
- [ ] «или при выходе» → «Отправлю, когда выйдешь из игры.» без перезагрузки, рядом «Отправить». Выйти на экран персонажей и зайти → Wisp ждёт ответ («Я этим занят…»), запрос виден в MCP `list_requests`.
- [ ] Ответить на запрос (MCP `list_requests` → `put_plan`). Тост Companion «New plan ready. Wisp picks it up next time you log in.», в окне «Your plan is ready in the game».
- [ ] После обычного для планировщика времени (по умолчанию ~3 мин) Wisp пишет «Должно быть готово. Обновить?» и «Обновить» — только если Companion уже записал этот запрос как готовящийся. До этого никакого «Обновить» в облачке нет.
- [ ] «Обновить», а ответа ещё нет → «Почти. Дай мне ещё пару минут.», следующее «Обновить» не раньше чем через 2 мин.
- [ ] Ответ пришёл → «План получше готов! Берём?» → «Сменить».
- [ ] «Что-то другое...» → поле желания и «Минуты» → «Дальше» → то же подтверждение, в пересказе — твоё желание в кавычках.
- [ ] Старый запрос не перебивает новый: отправить запрос A, потом запрос B. Ответить на B (`put_plan` с `requestId` B), потом `fail_request` для A. Companion пишет в `Plan.lua` ответ на B; после «Обновить» в игре план B, без петли «готово → обновить → ничего нет».
- [ ] Шаги отмечаются сами (или ✓). В конце звук и «Всё сделано, отлично! Что дальше?».
- [ ] Выйти с незаконченным планом и войти: «С возвращением! Продолжим «…» или что-то новое?».

## Ссылки в плане

Через MCP `put_plan` положить план, где в шагах есть `{item:6948}`, `{quest:ID}` (квест не из журнала), `{ach:964}`, `{spell:ID}`, `{currency:ID}`, `{npc:ID}` с `entities.npc` и `{pin:MAPID:52.1:47.3|метка}`. В ответе `put_plan` поле `warnings` пустое.

- [ ] В облачке каждая ссылка выглядит как в чате: предмет цветом качества, квест жёлтым, имена — из игры (на языке клиента), а не из текста плана.
- [ ] Наведение на предмет, квест, ачивку, заклинание, валюту — родной тултип игры. Наведение на НИП — имя, зона, координаты и «Клик: поставить метку». На метку — зона и координаты.
- [ ] Клик по НИП или метке ставит метку на карте и стрелку (и TomTom, если он стоит). Клик по предмету и прочим — как клик по ссылке в чате. Shift-клик вставляет ссылку в строку чата.
- [ ] Квест, которого нет в журнале: сначала метка из `|label`, через секунду — название из игры.
- [ ] Неверный id (например `{item:999999999|Пусто}`, положить через `answer_request`, сервер без ключа Blizzard): через ~3 с остаётся простой текст «Пусто», без ссылки и ошибок. После выхода в MCP `data_catalog` / секция `unresolvedIds` содержит этот id.
- [ ] В трекере и полном списке шагов — те же имена простым текстом, без `{…}` и без `|H`.
- [ ] Ошибок Lua нет, taint нет (после кликов по ссылкам сумки и чат работают в бою).

## Спросить

- [ ] Меню → «Спросить» → «что тут есть рядом» → сразу «Вот что есть рядом:» (без ПК и без перезагрузки).
- [ ] «какие ачивки тут» → «Достижения, которые можно делать здесь:». То же по-английски («achievements here»).
- [ ] Вопрос, на который Wisp не знает ответ → «Здесь я на это не отвечу. Сделать из этого план?» и «Сделать план». Клик → поле «Что-то другое» уже с текстом вопроса → дальше как свой план. Сам вопрос никуда не отправляется и UI не перезагружается.
- [ ] Без Companion: «Здесь я на это не отвечу. С Unbored Companion на ПК ответит планировщик.», без «Сделать план».

## Предметы

- [ ] Меню → «Что это за предмет?» → «Возьми предмет из сумки, и я посмотрю. Esc — отмена.» Клик по предмету — предмет в облачке. Esc отменяет.
- [ ] Взять предмет курсором: у Wisp подсказка «Брось на меня, чтобы спросить». Бросить — предмет в облачке, предмет вернулся в сумку.
- [ ] После всего этого сумки работают в бою (taint нет).

## Подсказки в тултипе

- [ ] Хлам, зелья, обычная броня, неизвестный предмет: строки Wisp **нет** вообще (ни «продай», ни «брось на Wisp»).
- [ ] Игрушка / маунт / питомец / облик, которого нет ни у одного персонажа аккаунта: «Wisp: Новое для коллекции». У того, что уже есть, строки нет.
- [ ] Предмет из шага текущего плана: «Wisp: Нужно для плана: <шаг>», шаг простым текстом (без `{…}`).
- [ ] Предмет, начинающий задание, которое этот персонаж ещё не делал: «Используй: начинает «…»». Если задание уже выполнено — строки нет.
- [ ] С альтами: реагент чужой профессии, когда у альта она есть: «Отправь <альт> (<профессия> <навык>): почтой» (тот же сервер и фракция) или «через банк отряда». Без альтов с этой профессией строки нет. Реагент своей профессии — строки нет.
- [ ] Альт с другого ПК: войди альтом-алхимиком на другом компьютере (Companion на нём подключён к тому же Аккаунту), дождись синхронизации Companion и нажми Обновить на этом ПК. Реагент алхимии у персонажа без алхимии показывает «Отправь <альт> …», хотя этот альт здесь ни разу не заходил.
- [ ] Эпик и BoE никогда не «продай»; привязанное — никогда не «отправь»; «удали» не бывает вообще.
- [ ] Меню → «Настройки» → «Строки Виспа в подсказках» выключить: строк Wisp нет нигде. Включить — вернулись.
- [ ] Личный совет: MCP `put_item_advice` для предмета → через ~30 с Companion обновил `Advice.lua` → после входа строка из совета в тултипе.

## Ошибки и ожидания

- [ ] Выйти из Companion (трей → Quit), отправить запрос → «На ПК не запущен Unbored Companion. Запусти его, и я всё подхвачу.»
- [ ] Выключить интернет на ПК, отправить запрос → «Unbored Companion не может достучаться до планировщика. Он пробует сам.» Включить — дошло.
- [ ] Запрос без ответа дольше 10 мин (видно после следующего входа) → «Что-то долго. Попробуй ещё раз или подожди.» и «Ещё раз».
- [ ] `fail_request` → «У меня что-то пошло не так. Попробуем ещё раз?», «Ещё раз» и «Понятно». «Ещё раз» возвращает к «Отправить это планировщику?» с тем же выбором, без перезагрузки.
- [ ] Запрос без ответа больше часа: сервер сам закрывает его, Wisp пишет «Этот запрос потерялся. Попробуем ещё раз?».
- [ ] Нигде нет сырых ошибок, id или просьбы набрать команду.

## Бой

- [ ] Войти в бой: облачко пропадает, Wisp полупрозрачный. После боя всё вернулось. Ошибок нет.

## Обновления

- [ ] Установка с 0.5 Companion обновилась сама до 0.6.0 (в течение ~20 с после старта или 4 ч).
- [ ] При обновлении аддона при запущенной игре: тост «I updated Wisp. Click Load in Wisp's bubble once to finish.», Wisp: «Меня обновили! Нажми «Загрузить», чтобы закончить обновление.». После «Загрузить» — новая версия; если нет — Wisp просит перезапустить игру.
